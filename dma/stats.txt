My estimate: **about 1 billion Google Search queries per day from the EU**, with a plausible rough range of **~0.8 to 1.5 billion/day**.

There is no official public Google figure for “daily Google searches from the EU,” so this is a derived estimate.

## Sources and calculation

Google said in March 2025 that it sees **more than 5 trillion searches on Google annually**. That implies:

```text
5 trillion / 365 ≈ 13.7 billion Google searches per day globally
```

Google’s source note for that figure is “Google Internal Data, Jan 2025.” ([blog.google][1])

For the EU side, Google’s DSA monthly-active-recipient report says **Google Search in the EU** had:

```text
364.3 million average monthly distinct signed-in accounts
437.3 million average monthly distinguishable signed-out sessions
```

for January–June 2025. Google explicitly warns these counts are **not comprehensively de-duplicated**, so you should **not add them together** as unique users. 

As a sanity check on the size of the EU online population: ITU estimated **5.5 billion people online globally in 2024**, and Eurostat reported that **93% of EU residents aged 16–74 used the internet in the previous three months in 2024**. ([ITU][2])

A simple proportional estimate is:

```text
Global Google searches/day ≈ 13.7B
EU Google Search active base ≈ 350M–450M
Global internet users ≈ 5.5B

EU share ≈ 350M–450M / 5.5B ≈ 6.4%–8.2%

EU Google searches/day ≈ 13.7B × 6.4%–8.2%
                     ≈ 0.9B–1.1B/day
```

Then I would widen that to **~0.8–1.5B/day** because EU users may search more often than the global average, but the DSA recipient numbers can also overcount individuals.

So the clean answer is:

> **Rough estimate: around 1 billion Google searches per day from the EU.**
> I would not treat it as more precise than “hundreds of millions to low billions per day.”

Using 1B daily searches, assuming 1kb per record, we get 1Tbyte of transmission daily.

According to ChatGPT, processing this would cost around 5$ per day on AWS:

Given **negligible output** and **immediate deletion**, I’d estimate:

> **~$1–$6 total on AWS for 1 TB**, depending on how you implement it.

The big costs mostly disappear because inbound transfer to S3 is free, S3 charges storage by object size and how long it is stored, and DELETE requests are free. You would still pay small S3 request charges and compute while the scan runs. ([Amazon Web Services, Inc.][1])

## Option A: stream to EC2 and scan directly

This is likely the cheapest if you can arrange it.

```text
Internet upload into EC2/S3:     ~$0
EC2 compute for a few hours:     ~$0.25–$2
Temporary disk, if needed:       ~$0–$1
Output storage/transfer:         negligible
Estimated total:                 ~$1–$3
```

A modest EC2 instance such as `m7i.large` is listed around **$0.1008/hour** in us-east-1 by Vantage’s AWS instance tracker; AWS’s own EC2 pricing page states On-Demand instances are billed by hour/second with no long-term commitment. ([Vantage][2])

## Option B: upload chunks to S3, process, delete each chunk

This is probably the easiest robust setup.

```text
Inbound data transfer:           ~$0
S3 temporary storage:            near $0
S3 PUT/GET requests:             cents, unless using tiny chunks
EC2/Lambda/Batch compute:        ~$0.50–$3
Estimated total:                 ~$1–$5
```

Request cost depends on chunk size. Roughly:

| Chunk size | Number of chunks for 1 TB | S3 request cost order of magnitude |
| ---------: | ------------------------: | ---------------------------------: |
|       1 GB |                    ~1,000 |                              cents |
|     100 MB |                   ~10,000 |                              cents |
|      10 MB |                  ~100,000 |                maybe tens of cents |
|       1 MB |                ~1,000,000 |                      a few dollars |

Use **S3 Standard**, not S3 Standard-IA or Glacier classes, because some cheaper storage classes have minimum storage-duration charges if deleted early. AWS’s S3 page notes 30-day minimums for Standard-IA / One Zone-IA and longer minimums for Glacier classes. ([Amazon Web Services, Inc.][1])

## Option C: S3 + Athena

This is very simple if the string search can be expressed in SQL.

```text
Athena scan of 1 TB:             ~$5
Temporary S3 storage:            near $0
S3 requests/results:             negligible
Estimated total:                 ~$5–$6
```

AWS’s Athena pricing example uses **$5 per TB scanned**: a 3 TB text scan costs $15, and a 1 TB compressed scan costs $5. ([Amazon Web Services, Inc.][3])

## Avoid this gotcha

Do **not** use S3 Transfer Acceleration unless you really need it. AWS lists accelerated data transfer into S3 from the internet at **$0.04/GB** from edge locations in the US, Europe, and Japan, which would add about **$40** for 1 TB. ([Amazon Web Services, Inc.][1])

So the concise estimate is:

```text
Cheapest custom streaming approach:   ~$1–$3
S3 chunked + custom processing:        ~$1–$5
Athena one-shot scan:                  ~$5–$6
```

I’d budget **$5** unless you need engineering convenience, in which case **Athena at around $5–$6** is a clean mental model.
